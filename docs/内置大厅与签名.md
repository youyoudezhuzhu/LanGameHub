# 内置大厅与固定签名

0.3.1 起，主机自己玩不再跳外部浏览器，而是用 App 内置的 WebView 加载本机服务；
编译签名也固定下来了。

## 1. 内置 WebView 大厅

### 改了什么

以前点「进入大厅」走的是 `startActivity(Intent.ACTION_VIEW)`，把页面丢给外部浏览器。
这带来两个问题：

1. **一跳出去 App 就退到后台**，`android:process=":hub"` 的服务进程随时可能被系统回收，
   于是只能再加 WakeLock / WiFiLock 去硬扛，费电又不一定扛得住。
2. **外部浏览器的地址栏、手势区、旋转处理**都不受控，全屏和横屏体验取决于浏览器。

现在改成内置 `HubWebActivity`（`android/app/src/main/java/net/langamehub/HubWebActivity.java`）：

- WebView 直接加载 `http://127.0.0.1:<port>/`，页面始终在 App 前台。
- 前台页面本身就是最好的保活，**因此去掉了 WakeLock 和 WiFiLock**，也删了
  `WAKE_LOCK` 权限和「锁屏时维持运行」开关。
- 页面里的 Fullscreen API（牌桌全屏按钮、蛇场全屏锁横屏）由
  `WebChromeClient.onShowCustomView` 接管，走真正的沉浸式全屏。
- 两个 Activity 都声明了 `configChanges="orientation|screenSize|..."`，
  **旋转时不重建 Activity**，页面靠已有的 CSS 断点自行重排 —— 和之前在浏览器里
  验证过的行为一致（168 项横竖屏检查覆盖了旋转用例）。

### 界面切换

原生界面（服务开关、二维码、房间、设置、诊断）和网页大厅之间要能来回切：

```
启动 App ──▶ 原生界面 ──「进入大厅」──▶ 内置大厅（WebView）
                 ▲                          │
                 └──────「主机」按钮 ────────┘
                        （按返回键也能回去）
```

- **网页 → 原生**：大厅页面右下角有一个半透明「主机」按钮。它只在
  `#/`、`#/gallery` 这类大厅路由下显示，进入对局后自动隐藏，不会压住牌桌顶栏和手牌。
  显隐由 WebView 里的 `HubShell` JS 桥实时同步路由决定。
- **切回不销毁页面**：用 `FLAG_ACTIVITY_REORDER_TO_FRONT` 把原生界面调到前面，
  WebView 保持存活，对局状态（牌局、房间连接）都还在。
- **原生 → 网页**：按返回键直接回大厅，而不是退出 App。
- **网页返回键优先级**：退出全屏 → 回退网页历史 → 切回原生界面。

### 安全边界

WebView 只允许加载本机地址，外部链接会被拦下并提示用浏览器打开。
文件访问、Content 访问、跨文件 URL 访问都关掉了。

## 2. 固定编译签名

### 问题

以前签名密钥是从 `HUB_DEBUG_KEYSTORE` 或 `.tools/debug.keystore` 取的，
`.tools/` 在 `.gitignore` 里。换一台机器编译就会生成**新的调试密钥**，
签名不同，Android 不允许覆盖安装，只能先卸载——一卸载，对局存档和设置就没了。

### 现在的做法

密钥固定在仓库里：`android/keystore/langamehub.jks`。

| 项 | 值 |
| --- | --- |
| 别名 | `androiddebugkey` |
| 口令 | `android` |
| 证书 SHA-256 | `62:ED:A7:74:AB:79:24:33:DA:E1:79:3A:05:BE:B1:02:8C:C2:F1:E9:E6:26:2A:91:78:11:46:A1:E0:53:23:52` |

编译脚本默认用它，编译完会把签名指纹打印出来：

```bash
./scripts/build-apk.sh
#     签名 Signer #1 certificate SHA-256 digest: 62eda774...52352
```

需要换密钥时用环境变量覆盖：

```bash
HUB_KEYSTORE=/path/to/my.jks \
HUB_KEYSTORE_PASSWORD=xxx \
HUB_KEY_ALIAS=xxx \
HUB_KEY_PASSWORD=yyy \
./scripts/build-apk.sh
```

细节和取舍见 [android/keystore/README.md](../android/keystore/README.md)。

### 兼容性

这个密钥就是之前 0.3.0 用的那一把（指纹相同），所以 **0.3.1 可以直接覆盖安装 0.3.0**，
不用卸载。以后只要仓库里带着这个 `.jks`，每次编译都能覆盖安装。

## 3. 保活方式的取舍

| 方式 | 0.3.0 | 0.3.1 |
| --- | --- | --- |
| 前台服务 + 常驻通知 | ✅ | ✅ 保留 |
| 内置 WebView 常驻前台 | ❌（跳浏览器） | ✅ 新增，主要手段 |
| `PARTIAL_WAKE_LOCK` | ✅ | ❌ 移除 |
| `WIFI_MODE_FULL_HIGH_PERF` | ✅ | ❌ 移除 |
| `WAKE_LOCK` 权限 | ✅ | ❌ 移除 |
| 「锁屏时维持运行」开关 | ✅ | ❌ 移除 |

理由：主机自己就在 App 前台玩，前台进程不会被回收，两个锁属于纯耗电。
前台服务本身保留，这样临时切出 App（比如回个微信）时服务还能活一阵，
从通知点回来就能继续。

## 4. 验收

已经验证的：

- 内置 WebView 模拟环境：旋转不重建页面、无横向溢出、Fullscreen API 生效 —— 8/8。
- 路由上报：大厅显示「主机」按钮、对局隐藏、hashchange 会通知原生层 —— 全部正确。
- 同源连接：`ws://127.0.0.1:<port>/ws` 握手正常，`/api/status` 正常，**无任何外部请求**。
- 从 0.3.1 APK 里解出的网页资源重跑横竖屏全量检查：**168/168 通过**。
- APK 内容核对：`HubWebActivity` 已编译进 dex、manifest 有 `configChanges`、
  `WAKE_LOCK` 权限已移除、签名与 0.3.0 一致。

尚未验证（需要真机）：

- 内置 WebView 的实际全屏观感、横屏锁定行为。
- 从大厅切到原生设置再切回来的对局状态保持。
- 不同厂商 WebView（系统 WebView 版本差异）。
