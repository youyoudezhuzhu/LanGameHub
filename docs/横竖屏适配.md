# 横竖屏适配

本版把 12 款玩法全部做成横竖屏双布局，只有射击玩法「港区防线」保持横屏独占。

## 结论

| 玩法 | 竖屏 | 横屏 | 说明 |
| --- | --- | --- | --- |
| 斗地主 | ✅ | ✅ | 三人牌桌，竖屏收窄两侧牌区、手牌按宽度重排 |
| 掼蛋 | ✅ | ✅ | 同上，队伍信息与出牌区在竖屏下改为纵向堆叠 |
| 德州扑克 | ✅ | ✅ | 椭圆座位圈在竖屏下改用更小的半径，左右座位不再出屏 |
| 四川麻将 | ✅ | ✅ | 竖屏下左右两家的河流改窄，手牌按可用宽度算牌宽 |
| 中国象棋 | ✅ | ✅ | 竖屏改为「棋盘在上、侧栏在下」堆叠 |
| 国际象棋 | ✅ | ✅ | 同上，共用 `DuelLayout` |
| 魔法出包 | ✅ | ✅ | 竖屏下对手座位槽位重排，石头架压缩 |

| 港区防线（Saltline） | ❌ 仅横屏 | ✅ | 射击玩法，竖屏时提示旋转手机 |

## 实现方式

### 公共能力

新增 `games/deskpark/apps/web/src/lib/fullscreen.ts`：

- `useFullscreen()` —— 订阅全屏状态。
- `toggleFullscreen(el, orientation?)` —— 切换全屏，失败时给出中文提示；传 `'landscape'` 时顺便尝试 `screen.orientation.lock('landscape')`。
- `enterFullscreen` / `exitFullscreen` / `lockOrientation` / `fullscreenSupported`。

`lib/media.ts` 扩展了方向相关的 hook，全部基于 `matchMedia` 订阅，旋转会触发重渲染：

- `useOrientation()` → `'portrait' | 'landscape'`
- `usePortrait()` → 竖屏为 `true`
- `useViewport()` → 当前视口像素尺寸，`resize` 与 `orientationchange` 都会更新
- `useCompact()` / `useSeatScale()` 保持原有语义，另外补了 `orientationchange` 监听

### 全屏入口

- **大厅**：顶栏新增全屏按钮（`screens/Home.tsx`）。
- **牌桌**：顶栏新增全屏按钮（`screens/TableShell.tsx`），11 款玩法共用，不需要各自实现。
- **流光蛇场**：因为它自己管 `.table--arena` 的全屏与方向锁，`TableShell` 对它跳过通用按钮，由 `SnakeBoard` 复用 `lib/fullscreen.ts`。
- 全屏对棋牌类**不锁方向**，跟着手机转；只有蛇场在全屏时尝试锁横屏。

### 各玩法的布局策略

两种手段，按是否需要在 JS 里算像素来选择：

1. **纯 CSS**：用 `@media (orientation: portrait)` 覆盖。适用于布局本身由 flex / grid 决定的玩法。
2. **JS 判断 + 重算**：用 `usePortrait()` / `useViewport()`，或者复用各玩法已有的 `ResizeObserver`（`useBox`）。适用于需要按像素算牌宽、棋盘边长、座位坐标的玩法（德州、宝石商会、魔法出包、四川麻将、棋类）。

棋类的 `DuelLayout` 新增竖屏堆叠分支，并新增 `sideFoot` prop：竖屏时侧栏上半部分可滚动（对手信息、着法），底部固定区放操作按钮和自己的信息卡，保证按钮不会被滚动藏起来。

## 验收

### 自动体检

`.work/orientation-audit.mjs`（未纳入仓库，属于开发期工具）对每款玩法跑 7 档视口，每档还会**不刷新页面旋转一次**再检查：

```bash
BASE=http://127.0.0.1:8787 GAMES=doudizhu,guandan,texas,sichuan,xiangqi,chess,spellstones,onecard,hexisle,gemguild,snake,highcard \
  node orientation-audit.mjs
```

判定规则：可见元素的包围盒超出视口 1px 以上就报错，以下情况豁免——

- 元素被 `overflow: auto/scroll` 的祖先接管（内容在设计上可滚动）；
- 元素被明显小于视口的 `overflow: hidden` 容器裁掉（卡片里的装饰插画）；
- 元素在 `aria-hidden="true"` 的装饰子树里。

铺满视口的 `overflow: hidden` 容器（`.table` 就是 `inset: 0`）**不豁免**，所以玩法里被屏幕边缘切掉的内容仍然会被报出来。

覆盖的视口：360×640、390×844、412×915（竖屏手机）、844×390、915×412（横屏手机）、768×1024（平板竖放）、1024×768（平板横放）。大厅与设置面板另外覆盖到 1280×800、1920×1080。

### 回归要求

- 全部视口 `ok`，含旋转用例。
- 截图逐张确认：竖屏下该看见的座位、手牌、棋盘、按钮都在视口内，主内容不小于可用面积的合理比例，按钮不被安全区或刘海遮挡。
- 横屏与桌面尺寸的截图必须与改动前一致或更好（现有 `max-height: 500px` / `460px`、`min-width: 1100px` 断点行为不退化）。
- `npx tsc -p apps/web --noEmit` 无报错；`npx eslint` 不新增 error。

## 已知限制

- 全屏依赖浏览器的 Fullscreen API。iPhone 上的 Safari 不支持把任意元素全屏，按钮会提示把站点添加到主屏幕；此时用主屏幕书签以 `standalone` 模式打开同样能全屏。
- 方向锁定依赖 `screen.orientation.lock`，只有先进入全屏、且在 Android Chrome 等支持的浏览器上才生效。锁不住时蛇场仍然按当前方向布局，玩家自己转手机即可。
- 竖屏布局优先保证「全部内容可见且可点」，牌桌类玩法在很窄的竖屏（≤360px 宽）上牌会明显变小，属于取舍而非缺陷。
