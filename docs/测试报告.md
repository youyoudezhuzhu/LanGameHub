# LAN Game Hub 0.1.0 测试报告

本次交付为调试 APK，SHA‑256 为 `d1b43003111c25c3924fff63541f658e16c71853b519e611d3dc475e1c1a284a`。测试分为规则与服务端、桌面浏览器和 Android 模拟器三组。实体设备清单在文末。

## 构建和静态检查

- SDK Build Tools 35.0.0 生成并签名 APK。签名方案 v2、v3 校验通过，包名 `net.langamehub`。平台配置为最低 API 26、目标 API 35，包内包含 ARM64 和 x86_64。
- 桌游 Web/Vite、服务端单文件和 JNI 库均构建成功。TypeScript 类型检查通过。上游 Vitest 在 CI 阈值下运行 22 个测试文件和 222 项测试，包含规则、随机对局、协议、房间和输入校验。
- Gradle 配置随安卓工程交付，本次产物使用 `scripts/build-apk.sh`。构建环境未成功通过 Gradle 拉取 Android Gradle Plugin。

## Android 模拟器

- 在 API 28、x86_64 软件模拟器完成 APK 安装、原生主机界面启动和 JNI 内嵌 Node 进程启动。原生诊断的 HTTP 与 WebSocket 升级均正常。
- 通过 ADB 端口转发连接 APK 内服务。两个客户端验证十款游戏的房间、状态、重连和退出。连续三轮均正常，每轮最多三个并发房间，结束时房间数归零。国际象棋每轮完成四步将死。
- 使用 Home 键将界面退到后台，以及关闭模拟器屏幕 8 秒后，HTTP 均保持响应。重启产生新的服务进程并恢复 HTTP。停止服务使 HTTP 端口关闭，再启动恢复响应。
- 主机管理 API 正确报告双人房，管理员解散后两位客户端都收到退出通知。
- 为模拟器虚拟网卡配置测试地址后，原生界面更新为 `http://10.0.2.15:8787/`。对截图中的二维码执行解码，得到同一个 URL。对局测试使用 ADB 转发，这个二维码测试仅验证输出内容。
- `dumpsys meminfo` 记录服务进程启动后的 PSS 约 56 MiB，三轮协议测试后约 67 MiB。原生诊断曾记录 133 MiB RSS。这是软件模拟器短测，未做长时泄漏判断。
- 交付 APK 内的服务端 bundle 与模拟器中通过测试的 bundle 校验值一致。
- 初始测试发现该运行库的 `Buffer.toString('base64url')` 在玩家握手时抛出 `RangeError`。改用同一随机字节的十六进制表示后，重新通过实际 Android WebSocket 测试。
- 模拟器的虚拟 Ethernet 入站转发未通过，测试改用 ADB。ARM64、实体 Wi‑Fi、手机热点、厂商电源和现代 Android 前台服务仍待验证。

## 实体 Android 设备验收

本次环境没有实体 Android 手机。下列项目仍需验收。

1. 手机 A 安装 APK。连接 Wi‑Fi，打开服务。手机 B 扫描二维码，手机 C 复制链接，手机 D 手动输入完整 IPv4 地址。核对每台浏览器的大厅、在线计数、房间槽位、聊天与实时状态。
2. 至少走完一局国际象棋，全部退出回大厅。在相同浏览器中换另一种游戏，确认昵称、建房和加入行为。再逐项检查其他游戏的规则说明、触屏操作、异常退出和结算。
3. 断开外部互联网。保留同一个 Wi‑Fi 局域网，再测试一次。切换为手机 A 开热点，B/C/D 连接热点并再次执行。检查热点休眠、多网卡和路由器客户端隔离。
4. 测试锁屏、退到桌面、多轮建房、刷新和断网恢复。核对通知和活动连接，记录 30 分钟以上的 RSS/PSS、性能、发热和电量。检查端口占用、自定义端口、停止和重启，以及应用进程被系统回收后显示的状态。
5. 分别验证 Android 8.x 和现代 ARM64 设备，记录 4 KiB / 16 KiB 页大小。不同 Android 版本、厂商后台策略、WebView 或浏览器兼容不能由 x86_64 模拟器外推。

Slithering.io、Saltline 和 pvz_perf 未包含在 APK，它们的联机、触屏、汉化和单机交付项未通过产品验收。Saltline 的上游单独构建及 45 条多人协议检查通过，未计作 LAN Game Hub 功能。

## 复现

桌面服务用 LAN 模式和机器 IPv4 运行。执行前关闭其他测试房间。

```sh
python3 tests/lan_protocol.py http://<运行地址>:8787 --cycles 3
python3 tests/browser_smoke.py http://<运行地址>:8787 docs/screenshots
```

使用 `adb forward tcp:18787 tcp:8787` 可对已经启动的 Android 服务运行同一份协议测试。该路径适用于模拟器或 USB 调试，实体 Wi‑Fi 和热点需要独立验证。
