## 0.2.0 接入边界

- 三个仓库的默认分支仍是表中的提交。Slithering.io 仍无明确再分发许可证。阶段 D 上线原创的「流光蛇场」，使用独立实现的规则、素材与 Canvas 界面。阶段 D 复用 LAN Game Hub 的房号、身份、房主权限、断线重连和统一结算操作。
- Saltline 原始项目 `realskyrin/fps3ademo-saltline` 的 GitHub 许可证为 null，许可证端点返回 404。CandGo 仓库明确保留原件和上游条款。已在独立工作区重跑联机中继的 45 项断言。整合和分发仍需确认原始游戏代码及素材的授权。获得授权后，以现有 WebSocket 中继接入同端口路由，复用合作/对抗逻辑，停用 P2P 发现路径并逐项验收触屏和画质。
- PvZ 的 GitHub 网页附件需要匹配的 `pvz-perf.data`，且其清单标记为 Bilibili 发行。自用构建现在可导入合法取得的完整上游离线 Web 包。导入校验配套清单和文件摘要，加入统一大厅入口，并保留上游存档流程。默认 APK 继续排除该游戏及原版资源。对照用户提供的网盘清单，发现 v4.0.6 Windows 与 Android 完整包和资源备份。清单未列出完整离线 Web 包或素材再分发许可证。

## PvZ 双人合作调研

`Board::MouseDownWithPlant` 和工具输入当前直接修改本地局面。候选改造需先将种植、铲除和拾取动作转换成有编号、可校验的命令，由一个权威实例在固定步长处理。权威层需覆盖 `Board::UpdateGame`、对象更新、阳光生成和僵尸波次。快照按玩家可见范围发布，基础版本先实现全量重连快照，再评估增量同步。另开合作入口和存档空间，保留单人程序、设置与 IndexedDB 行为。当前缺经确认的离线资源包，未进行真实关卡或合作对局验证。
